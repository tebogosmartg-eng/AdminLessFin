# Payroll Export — Implementation Summary

**Module:** Payroll Export  
**Certification date:** 29 July 2026  
**Governing ADR:** [ADR-0002](../adr/ADR-0002-payroll-export-certification-architecture-freeze.md)

---

## Scope delivered

1. **Payslip PDF / UI polish**
   - Employer logo, name, and address remain primary header branding.
   - AdminLess Fin appears only in a subtle “Generated by” footer.
   - Payment block includes method, bank name, full account number, branch code, and reference.

2. **Bank payment file (CSV)**
   - Columns: Employee Name, Bank Name, Branch Code, Account Number, Amount, Reference, Payment Date.
   - Banking fields sourced from employee master data via Edge-returned `bank_rows`.

3. **Deployment alignment**
   - Live `GENERATE_BANK_BATCH` made the single source of truth for bank payment rows.
   - Frontend consumes `bank_rows` directly; run-detail rebuild is emergency fallback only.

4. **Schema support**
   - Migration `20260729100000_employee_bank_branch_code.sql` adds `employees.bank_branch_code` and is applied on the linked production project.

## Architecture (certified)

```
PayrollCommandCentre / PayrollRunDetail
        │
        ▼
 invokePayroll({ method: 'GENERATE_BANK_BATCH' })
        │
        ▼
 payroll Edge Function (v30+)
   • load payslips (net_pay)
   • load employees master (bank_*)
   • persist bank_batch metadata
   • return { bank_rows, bank_batch, run, persisted }
        │
        ▼
 downloadBankPaymentFile(bank_rows)  ← no reconstruction when bank_rows present
        │
        ▼
 CSV / bank file for Excel / banking upload
```

## `bank_rows` contract (authoritative)

Each row includes at minimum:

| Field | Purpose |
|-------|---------|
| `employee_name` | Payee display name |
| `bank_name` | Bank institution |
| `bank_branch_code` | Branch / sort code |
| `bank_account_number` | Account number (full) |
| `net_pay` / `payment_amount` | Payment amount |
| `reference` / `payment_reference` | Payment reference (e.g. `PAY-{pay_date}`) |

Serializers must prefer these fields and must not require the client to re-query incomplete embeds for the happy path.

---

## Explicit non-goals

- No changes to payroll calculation engines or statutory formulas.
- No redesign of payroll run lifecycle (create → approve → process → finalize).
- No replacement of double-entry posting ownership.
